# Junctions：多车交汇配套世界

状态：世界、真实 SLAM 地图及坐标接线已完成；固定程序通过29条单车任务、合法位移后继续同一原任务，以及双车启动就绪。该结论仅为配套环境与单车前置基线。

## 交付边界

先独立交付仿真世界、实际 SLAM 地图、站点与初始位姿。各区域的单车正常导航通过后，才允许用它验证多车干预。此交付不实现多车检测、决策、通信或解锁动作。

几何由本仓新建，manifest 的 `source_sha` 留空；机器人模型仍固定在 `deploy/assets/EASYGO_WORLD_SOURCE_SHA` 所记录的 EasyGo 修订，不更换模型来源。World、程序镜像及版本仍独立。

## 几何与坐标

单位为世界坐标米，x 向右、y 向上。所有区域通过 y=0 的宽主通道连接，场地外部为实心碰撞几何，局部任务没有墙外绕行路径。

| 区域 | 中心/端点 | 约束与用途 |
|---|---|---|
| 主通道 | (-13,0) ↔ (13,0) | 净宽 2.6，端部 3×3，宽道及正常通行对照 |
| T 路口 | (-8,8)；西 (-13,8)、东 (-3,8)、南 (-8,3) | 三臂净宽 0.9，交点扩大至 1.3×1.3；两端 3×3 |
| 十字路口 | (8,7.5)；西 (3,7.5)、东 (13,7.5)、北 (8,11)、南 (8,3) | 四臂净宽 0.9，交点 1.3×1.3；西、东、北端有 3×3 空间 |
| 窄门 | x∈[-9,-7]、y∈[-6.45,-5.55] | 门净宽 0.9、深 2；左右均为 5×5 房间，只有此门连通 |
| 窄路回退 | (3,-7) ↔ (13,-7) | 净宽 0.9、两端 3×3；中间北侧待避区 x∈[6.7,9.3]、y∈[-7.45,-3.3]；同一湾口向南至 y=-7.65 留转向凹区 |
| 准备动作空间 | 待避区及东端 (13,-7) | 为对向车短移、另一车转入待避区分别提供可行空间；具体多车动作留待方案实现验证 |

短且不对称的墙凹口提供定位特征，不突出到车道里。初始位姿位于主通道端部：车 1 (-13,0,0)，车 2 (13,0,π)。

模型全部 14 个碰撞体（包括充电触点 STL）的名义投影包络为 x∈[-0.41,0.41]、y∈[-0.24,0.24]，即 0.82×0.48，高度约 1.112。0.9 净宽允许单车、禁止两车并排；地图、规划器 footprint 与物理包络分别核查，不能用规划器尺寸代替物理碰撞检查。发布程序默认 0.80×0.46 切角轮廓不足以覆盖物理模型，已在窄路返回实测触墙。仿真专用程序已按完整矩形、碰撞余量及已有倒车能力校准；原默认切角配置的通过条目不并入本基线。

SceneBroadcaster 的 `dynamic_pose_hertz=500` 仅提高真值观测频率，实测原始帧间隔 3 ms；物理步长仍为 3 ms。独立检查直接读取 Gazebo `Pose_V.header.stamp` 和完整四元数，以全车三维包围盒在地面的投影检查墙间余量。ROS truth bridge 会将 header 改写为 ROS `now()`，因此不作为连续间距证明的时间源。

## 验收门禁

1. 静态检查：实体墙带 collision；所有路线和待避点连通；切断四类瓶颈后对应端点不连通，证明没有外绕通路。
2. 实际驾驶建图：一个真实仿真车，遍历各臂、门两侧及整个实际使用的待避空间，回到开图起点后结束；生成导航资源并导出地图集。
3. 接线：实测世界与地图偏移，在相隔较远的特征区域复核；全部站点与初始位姿落在观测区域，重启后能正常定位。
4. 单车：实际只启动一个机器人，现有多车逻辑关闭；未来 A、B 两条路线分别完成，窄门双向、待避区进出和准备动作空间也必须通过。按独立物理真值检查全车碰撞包络及墙间余量；不以任务返回成功替代物理验收。
5. 恢复：正常暂停后在可行区域内改变位姿，继续原任务应完成；定位、导航和任务异常分别按源代码及日志归因。
6. 全部单车门禁通过后，才验证双车环境的实体、独立 API、地图及定位就绪。此步不代表多车解锁已实现或已通过。

任何世界、地图、车型包络、程序镜像、导航或定位配置变化，都重新执行受影响的单车门禁。后续候选多车镜像也先过同样的单车门禁。

单车使用 29 条独立普通任务，速度 0.3 m/s；每条要求原任务和站点均完成、真实位置误差≤0.15 m、朝向误差≤0.12 rad、定位有效。几何门禁要求连续墙间余量≥20 mm；证明使用保守速度界 1 m/s、角速度界 2 rad/s 及完整三维包络半径，不以稀疏采样的最小值替代帧间证明。末尾还需确认真实车体已静止。暂停位移用例只豁免明确记录的人为位姿跳变，位移前后包络必须位于当前真实可行区域，继续时保持原 task/run 和目标。

外部验收工具只连接本任务新建、独占控制的运行容器。车端 `/tasks/current/pause` 没有原子 run-id 条件；工具的暂停前后身份检查依赖“无其他任务控制者”这一前提，不适用于共享车。

## 启动与程序基线

```bash
go build -o simenv ./cmd/simenv
docker build -f deploy/Dockerfile -t simenv-world:junctions-20261027 .
./simenv start --world junctions --robots 1 \
  --env-image simenv-world:junctions-20261027 \
  --app-image simenv-app:release033-navcal3-20261027 \
  --data-root /tmp/simenv-junctions-baseline
./simenv status
./simenv stop
```

程序镜像为独立 EasyGo 运行镜像，使用 `release_0.33.x` 的 `docker/packages.env`：App 0.4.156、Nav2 0.4.6、Nav2 interfaces 1.5.4、VDA5050 0.3.75、sim-bringup 0.14.1、SLAM 0.2.48、perception 0.2.4。不得替换成包含先前多车修改的旧实验镜像。

当前 simenv EasyGo 边缘实现固定传入 `enable_multi_robot_wifi:=true`，环境变量关闭会被 launch 覆盖。上面的单车专用程序镜像在调用原 `/entrypoint.sh` 时追加 `enable_multi_robot_wifi:=false`，保留已发布的 App/Nav2 二进制，关闭双方现有干预；须从 App 启动日志及运行时参数复核。该程序镜像属于外部输入，不作为环境镜像的 FROM。
